# 卡片頁的欄位搜尋（handler field search）

日期：2026-10-25　分支：`feat/person-profile`　狀態：S1 實作完成（先開放給人脈卡）

## 1. 目的

卡片頁原本只有 Anki 語法的搜尋框（例如 `note:Person_Profile_Dark "Relationship:*客戶*"`），要記欄位的英文名與語法。
改成像卡片一樣的操作：選筆記類型 → 點「互動」→ 輸入「餐廳」，就能撈出這個類型所有符合的卡片；條件可以任意疊加（且）。

## 2. 設計

### 2.1 開放與否：handler 的能力宣告

- `HandlerCapabilities.search`（`Operation`）：沒寫就是不開放（`尚未開放`）。前端依 `GET /handlers` 的 `capabilities.search` 決定顯示，不用改前端。
- 開放一種卡片：在該 handler 的 `CAPABILITIES` 加 `search=Operation(supported=True)`，確認欄位按鈕合用後部署後端。

### 2.2 欄位按鈕

- `BaseHandler.search_fields()`：有宣告 `SEARCH_FIELDS` 就用它；否則依 `CREATE_PARAMS`（媒體欄位除外）與 `JSON_FIELD_SPECS` 自動產生，一個欄位一顆按鈕。
- `SearchField(key, title, fields)`：一顆按鈕可以比對多個 Anki 欄位（任一個包含即可），例如人脈卡的「名字」比對六個姓名欄位。
- 鍵 `*` 保留給「全部欄位」（前端固定放在第一顆）。
- 註冊表檢查：開放就要有按鈕；鍵不重複、不用 `*`；每顆按鈕至少對應一個欄位。
- 人脈卡宣告了 17 顆：名字、關係、公司、職稱、工作、興趣、飲食、個性、認識、出身／現居、互動、待追蹤、家人、禮物、重要日期、聯絡方式、備註。

### 2.3 組查詢（後端）

- `POST /handlers/{name}/search-query`，body `{"conditions": [{"field": "interactions", "value": "餐廳"}, ...]}`，回 `{"query": "..."}`。不碰 Anki。
- 限定 handler 負責的筆記類型；每個條件是「包含」（`"Field:*值*"`，值照字面比對，萬用字元等跳脫）；多欄位的按鈕以 OR 組合；條件之間是「且」；空白的關鍵字略過。
- 值含 `&`、`<` 等時，同時比對 HTML 轉義後的寫法（JSON 欄位與 Anki 編輯器存的是轉義後的文字）。
- 錯誤：不開放 400（`HANDLER_OPERATION_UNSUPPORTED`）；不能搜尋的欄位鍵 422（`INVALID_NOTE_FIELDS`）。
- 組好的查詢交給現有的卡片清單搜尋（`/cards` 的 `q`），分頁、牌組篩選照舊。

### 2.4 畫面（前端）

- 清單面板上方：「欄位搜尋」選單（不使用／開放的類型）→ 欄位按鈕列 → 條件列（欄位名、輸入框、移除），第二個條件起標「且」→「搜尋」「清除條件」。
- 選了類型時，原生的 Anki 語法搜尋框收成「進階：Anki 語法」（展開可看、可改組好的查詢）；沒選類型時照常展開。
- 類型與條件記在 localStorage（`cards_field_search`），回到頁面時還在。

## 3. 限制

- JSON 清單在 Anki 裡是一整串文字：「互動 包含 餐廳」比對的是那一欄的全部內容（日期、地點、聊什麼、近況、原話），不能指定子欄位（例如只看地點）。
- Anki 語法做不到的篩選（例如「很久沒聯絡」）不在這一階段。
