# 三語對話卡：參考答案的熟識度（0–9）

日期：2026-10-30　分支：`feat/person-profile`　卡片：`Speaking_Trilingual_Dark`

## 1. 目的

同一個情境，對不同關係的人說法不同。每句參考答案加一個「熟識度」0–9（0＝陌生、正式，9＝最親密、最隨意），
在卡片背面以刻度條顯示，並讓錄音評分知道每句參考答案的熟識度。
場合與對象的其他資訊照舊寫在卡片正面的 `Context`（例如「對方是熟識的朋友」）。

## 2. 決定

| 項目 | 決定 |
|---|---|
| 維度 | 只有一個：熟識度 0–9（多維度方案太複雜，其餘靠正面描述） |
| 方向 | 0＝最正式（正式場合、對重要的人）；9＝最親密、最隨意 |
| 存放 | 參考答案那筆 JSON 多一個鍵 `familiarity`（整數 0–9，可省略）；不改筆記類型的欄位 |
| 顯示 | 刻度條（十格，熟識度 N 填滿 N＋1 格）＋數字，放在每筆的標題列右側 |
| 顏色 | 三段：0–3 藍、4–6 紫、7–9 粉紅到火紅；同段內越親密越鮮豔，9 最鮮豔（見 §3.2） |
| 排序 | 各語言的參考答案依熟識度由低到高顯示；沒填的排最後；深連結與狀態切換仍用原本的序號 |
| 沒填 | 舊答案沒有 `familiarity` 時不顯示刻度條，其餘照常 |

## 3. 改動

### 3.1 資料與匯入

- `familiarity`：整數 0–9（`7.0` 這種整數值的浮點數也接受）；省略、`null`、空字串表示未標（匯入時移除這個鍵）。只含半形數字的字串（例如 `"7"`）匯入時轉成整數；其他值（布林、小數、全形或上標數字、`"7.0"`、超出範圍）匯入時報錯並略過該卡，訊息指出欄位（例如 `References_JA`）與第幾句。
- 參考答案欄位不是 JSON 陣列（物件、數字）或 JSON 損毀時，同樣報錯並略過該卡。
- 檢查只在熟識度真的要改時才改寫欄位；參考答案的內文（`<br>`、HTML 實體、換行）一律保持原樣。
- 判斷規則後端與卡片 JS 相同，`tests/test_trilingual_familiarity.py` 以同一張對照表驗證兩邊（卡片 JS 用 node 執行）。
- `scripts/local_anki/Speaking_Trilingual_Dark/import_cards.py`：匯入前檢查（共用 `app/services/task_handlers/shared/trilingual_familiarity.py` 的檢查函式；錄音評分與樣板驗證器也用它）。
- `scripts/common/samples/speaking_trilingual_sample.json` 與樣板驗證器：範例加上熟識度，驗證器檢查範圍。

### 3.2 卡片背面（模板與 CSS）

- `Speaking_Trilingual_Dark_back.html`：`buildReferenceItem` 在標題列右側畫刻度條與數字；渲染前依熟識度排序（帶著原本的序號）。
- 顏色（0–9）：`#4a90c2`、`#5dade2`、`#6cb8e6`、`#82c4ea`、`#9b87f5`、`#a78bfa`、`#c084fc`、`#ff6b9d`、`#ff3d6e`、`#ff1f3d`；9 加一圈淡光暈（沿用狀態圓點的作法）。
- 標題列的「錄音 N・參考 N」不變。

### 3.3 錄音評分

- 評分器介面（`BaseAudioEvaluator.evaluate_audio` 與各實作）多一個選填參數 `reference_familiarity: list[int | None] | None`，與 `reference_answers` 一一對應；交給提示詞樣板。純文字清單 `reference_answers` 不變（stt_diff 只比對文字）。
- `voice.py`：讀參考答案時一併取出熟識度（只取啟用中的答案，與文字同步過濾）。
- 三語評分提示詞（`Speaking_Trilingual_{ZH,JA,EN}.j2`）：
  - 參考回答列出熟識度，並說明 0–9 的意思。
  - 評分規則多一條：依 Prompt／Context 判斷對象與場合，評估使用者的說法親疏是否得體（太生硬或太隨便都要在 feedback 指出，並給出合適的說法）；參考回答的熟識度是校準用的範例。
- stt_diff：比對到的參考答案有熟識度時，feedback 開頭註明「比對對象：熟識度 N 的說法」。
- 通用樣板 `audio_evaluator.j2`（對話卡）不動；對話卡的參考答案沒有熟識度。

### 3.4 不受影響

- handler 的 `add_audio`（替參考答案加音檔）就地修改那一筆，其他鍵保留。
- 卡片背面的狀態切換寫回整個 JSON（物件原樣寫回），熟識度保留。
- TTS（AI 產生參考答案語音）尚未實作，不受影響。
- 參考答案只從匯入腳本進來（handler 沒有「新增參考答案」的動作），所以沒有 TG 的新增流程要改。
- 例外：在 Anki 編輯器手動改欄位不經過任何檢查。卡片與評分都把不合格的值當成未標；評分時會記一行 warning（卡片與第幾句）。

## 4. 驗收

- [ ] 卡片背面：有熟識度的答案顯示刻度條與數字、顏色符合 §3.2、依熟識度排序；沒填的照常顯示在最後
- [ ] 排序後，替某一句加音檔、切換啟用狀態，動到的仍是同一句
- [ ] 匯入：熟識度超出範圍或格式不對時報錯並略過該卡；字串數字轉成整數
- [ ] 錄音評分（stt_llm／listen）：提示詞帶出各參考答案的熟識度與說明；stt_diff 註明比對對象的熟識度
