## 1. 背景與目標

使用者在 2026-11-14 提出三項，加上補欄位的檢討：

1. **工作經歷**要能調整順序，並且獨立成一個子項目；現職要比過去的工作明顯。
2. **卡面預設全部顯示**，在背面長按某一筆可以經 TG 設定隱藏或顯示；隱藏的那筆在卡面留下明顯的遮擋。
3. 加一個**帶時間的目標**欄位：證照、簽證、資格、努力方向、夢想、願景等。
4. 檢討「認識一個人」還缺哪些欄位，使用者選了：**共同點**、**對方需要的幫助**、**不喜歡的事**、**禮物靈感**。

## 4. 工作經歷（D1、D2）

### 4.1 格式

`Company` 的一筆加三個選填的鍵：

```json
{"company": "Geekly", "title": "顧問", "start": "2021-04", "end": "", "note": "負責 IT 業界的轉職", "added": "2026-11-14", "ended": ""}
```

- `start`、`end`：任職起訖，可只填年（`2021`）、年月（`2021-04`）或完整日期。已經離職但不知道時間，`end` 填 `?`（卡面顯示「～？」）。
- `note`：這份工作的說明（短的；長的專案內容照樣記在「工作內容」）。
- `added`、`ended` 的意義不變（登錄日、劃掉日）。
- **現職**＝沒有 `end`，而且沒有劃掉。舊資料沒有 `end`，所以有效的職位都算現職，和現在的行為一致。
- 指紋（`item_fingerprint`）不加這三個鍵：補填年月後，卡片上的舊連結仍對得上同一筆。

### 4.2 顯示

- **背面「工作」區塊**分兩段：
  - **現職**：每筆前面一個「現職」標籤，用強調色，字比過去的大一級。
  - **過去**：較淡，每筆顯示「公司・職稱（2019-04 – 2021-03）」與說明。
- **排序**：兩段之間現職一律在上；同一段裡照清單順序，也就是使用者在網頁調整的順序（使用者的第 1 點）。§9 Q1 問要不要改成依年月自動排。
- **正面**：認人卡的「職位」提示只列現職。
- **TG**：
  - 摘要只列現職。
  - 職位的「劃掉」改叫「離職」：填 `ended`＝今天；`end` 還空著時填這個月（`YYYY-MM`）。
  - 新增職位時多問「到職年月」，可以跳過。

### 4.3 網頁編輯

JSON 編輯器照模型畫表單：`Position` 加 `start`、`end`、`note` 三個欄位後自動出現；上移、下移已經有了。年月的格式檢查用 `^$|^\d{4}(-\d{2}(-\d{2})?)?$`。

## 5. 預設全部顯示與逐筆隱藏（D3、D4）

### 5.1 預設全部顯示

- 會變的欄位不再需要點眼睛：先列有效的，再列劃掉的（刪除線、較淡、附「登錄日・劃掉日」）。
- 興趣、飲食這類標籤欄位：劃掉的標籤接在有效的後面，較淡加刪除線。
- 欄位旁的眼睛拿掉。
- 「敏感話題」維持預設模糊，它是另一回事，不是這裡的隱藏。

### 5.2 隱藏的記法

| 對象 | 記在哪 | 理由 |
|---|---|---|
| 清單的一筆（六種 JSON 清單、會變的欄位、目標） | 項目加 `"hidden": true` | 項目模型本來就保留多餘的鍵；不放進指紋，隱藏後連結不失效 |
| 文字欄位（外貌、出身地、備註等） | 標籤 `人脈卡隱藏::<欄位名>`，例如 `人脈卡隱藏::Appearance` | 文字欄位放不下旗標；用標籤不改筆記類型（同「AI 內文不遮名字」的做法） |

### 5.3 卡面的樣子

- 隱藏的那筆（或那個文字欄位）換成一塊明顯的灰色斜線遮擋，寫「已隱藏・點一下看」。點了暫時顯示，翻下一張就恢復。
- 正面的提示（認人卡的職位、認識場合、外貌）也照樣遮擋：是隱藏的，正面就看到遮擋塊。

### 5.4 長按改成開 TG 的選單

長按 3 秒後，TG 不再直接刪除，而是先列出這一筆和可以做的事：

| 對象 | TG 選單 |
|---|---|
| 清單的一筆 | 隱藏（或顯示）、刪除；會變的欄位多一個「劃掉」；職位叫「離職」 |
| 文字欄位 | 修改、隱藏（或顯示） |

- 刪除照舊要再按一次確認。
- 深連結的動作碼新增 `pitm`（清單的一筆）與 `pfld`（文字欄位）。舊卡面上的 `pdel`、`pedit` 連結繼續可用，直到重新渲染。
- 隱藏只影響顯示：AI 分析、用一段話記錄照樣讀得到（§9 Q3 確認）。

## 6. 目標（D5）

新增 JSON 欄位 `Goals_JSON`，一筆：

```json
{"kind": "證照", "item": "日本語能力試驗 N1", "target": "2026-12-07", "status": "open", "added": "2026-11-14", "closed": ""}
```

| 鍵 | 說明 |
|---|---|
| `kind` | 類型：快速選項有證照、簽證、資格、升學、職涯、努力方向、夢想、願景，也可以自己填 |
| `item` | 內容（必填） |
| `target` | 目標時間：年、年月或完整日期，可空 |
| `status` | `open` 進行中、`done` 達成、`dropped` 放棄 |
| `added` | 登錄日（系統填今天） |
| `closed` | 改成達成或放棄的那天（系統填） |

- **背面**：新的「目標」區塊放在「工作」後面。
  - 進行中的依目標時間由近到遠排，沒有時間的排在最後。
  - 過期或 60 天內到期的標色。
  - 達成、放棄的接在後面，較淡，附標籤與日期。
- **見面前必看**：有完整日期、60 天內到期的目標，列進「近期」（同重要日期），例如「N1 考試（12/07，還有 23 天）」。
- **TG**：
  - 區塊的「+」新增：問類型、內容、目標時間。
  - 每筆的「達成」「放棄」。
  - 長按的選單同 §5.4。
- **AI**：
  - 用一段話記錄可以建議新增目標。
  - 「AI 分析與話題」把進行中的目標當聊天素材，例如「考試準備得如何」。
- 「個性與價值觀」的說明拿掉「夢想」，改由目標記。

## 8. 筆記類型的變更與 AnkiWeb 完整同步

要新增的 Anki 欄位：`Goals_JSON`、`Common_Ground`、`Needs`、`Dislikes`，一共 4 個。工作經歷和隱藏都不需要新欄位。另外拿掉「認人」卡片模板、把「見面前複習」改名成「人脈卡」（§12，D16）。

- 新增欄位、刪除與改名卡片模板都會讓 AnkiWeb 要求一次**完整同步**，所以放在同一支腳本一次做完，只同步一次。
- 執行前所有裝置（手機的 AnkiDroid／AnkiMobile、桌面）要先同步到最新；完整同步時在 NAS 的 Anki 選「上傳到 AnkiWeb」，其他裝置再下載。沒有先同步的裝置上的變更會遺失。
- 加欄位用既有的 AnkiConnect `modelFieldAdd`（`infrastructure/anki/client.py`），寫成一次性腳本放 `backend/scripts/local_anki/Person_Profile_Dark/`，先 `--dry-run` 列出要加的欄位。
- 執行時間由使用者決定（會動到真實的 Anki）。

## 15. 事件時間（2026-11-15 使用者：「全加上」，§15.3 的必要、建議、可選都做）

### 15.1 起因

TG 新增經歷時沒有問「什麼時候」。原因是 §14 把 `Experiences` 做成 `HistoryNote`（只有內容），每筆只有系統填的**登錄日**（`added`，記下的那天）和**劃掉日**（`ended`），沒有**事件時間**（那件事發生的時間）。爬過玉山是 2019 年還是上個月差很多（「後來還有去爬嗎？」和「上個月的玉山如何？」）。這是 §14 設計的疏漏。

### 15.2 已經有事件時間的

| 欄位 | 事件時間 |
|---|---|
| 職位 `Company` | 到職 `start`、離職 `end`（年、年月或日期） |
| 目標 `Goals_JSON` | 目標時間 `target` |
| 互動 `Interactions_JSON` | 日期 `date` |
| 待追蹤 `Followups_JSON` | 期限 `due` |
| 禮物 `Gifts_JSON` | 日期 `date` |
| 重要日期 `Key_Dates_JSON` | 日期 `date` |
| 家人 `Family_JSON` | 出生年 `birth_year` |
| 文字欄位 | 生日 `Birthday`、認識日期 `Met_Date` |

### 15.3 缺的（逐欄判斷）

| 優先 | 欄位 | 缺的時間 | 理由 |
|---|---|---|---|
| **必要** | 經歷 `Experiences` | 什麼時候（`when`） | 經歷本身就是「某個時間做過的事」；補記以前的事時，登錄日和實際時間差很多 |
| **必要** | 學歷 `Education` | 入學 `start`、畢業（實作叫 `finish`，原因見 §15.5） | 畢業年可以推算年紀、看出是不是同屆；目前只能把年份塞在文字裡 |
| **建議** | 目標 `Goals_JSON` 的結束日 `closed` | 實際達成、放棄的日子 | 現在按「達成」就填今天；N1 是 12/07 考過，晚幾天才按就會記錯。按的時候問日期，預設今天 |
| **建議** | 現居地 `Residence` | 搬來的時間 `since` | 「搬來東京三年了」是常見話題（舊的現居地劃掉日仍是新增那天，沒有改成新那筆的 `since`） |
| 可選 | 讚美素材 `Praise` | 什麼時候的成就 | 「去年拿到 MVP」有時間比較好讚美；但多半是近期的事，登錄日夠接近 |
| 可選 | 興趣 `Interests` | 從什麼時候開始 | 「玩貝斯十年」可以聊；但興趣是短標籤、新增要快，多問一步負擔大 |
| 不需要 | 飲食喜好、不喜歡的事、飲食限制、工作內容、個性與價值觀、可以請教的事、對方需要的幫助、共同點、溝通偏好、語言、時區、關係、親密度、敏感話題 | — | 是「現在的狀態」，登錄日和劃掉日已經夠用；有期限的事（例如找房子）放待追蹤 |

### 15.4 做法

- **資料**：時間存在每一筆的 JSON 裡（例如經歷 `{"value", "when", "added", "ended"}`）。**不動筆記類型、不用完整同步**，只換模板（換模板內容不會要求完整同步）。
- **格式**：沿用職位的 `PERIOD`（`YYYY`、`YYYY-MM`、`YYYY-MM-DD`），用 `normalize_period` 整理；都可以略過。
- **TG**：沿用職位「新增後追問」的做法（`POSITION_DETAIL_STEPS`），每個欄位一組追問步驟；長按某一筆可以改時間（把職位的 `edit_position` 做成通用的「改這一筆的時間」）。
- **卡面**：時間接在內容後面；經歷、學歷依時間新到舊排，沒有時間的排最後（實作見 §15.5）。
- **AI**：「用一段話記錄」的清單建議加一個通用的時間欄位，提示詞說明換算（「去年」→ 年）。
- **既有資料**：沒有時間的舊資料照常顯示，之後長按補上。

### 15.5 實作紀錄（2026-11-15）

## 16. 每一筆都能修改（2026-11-15 使用者：「照建議寫進計畫書並實作」，分支 `feat/person-item-edit`）

### 16.1 起因

TG 長按一筆的選單只有「在卡面隱藏、劃掉、刪除、回摘要」，有事件時間的欄位多一個「修改時間」，職位是「修改任職期間／說明」。**內容本身改不了**：打錯字（「去過玉山」想改成「爬過玉山」）只能刪掉重新新增，或到網頁的清單編輯器改。互動、待追蹤、禮物、家人、重要日期、聯絡方式、目標也都沒有修改。

當初沒做的原因：

- 會變的欄位的想法是「事情變了就劃掉、再新增」，舊的留成聊天素材；沒考慮到「記錯、打錯」的更正。
- 卡面長按與 TG 按鈕用內容算出的指紋認是哪一筆；內容一改指紋就變，所以 §11、§15 只做了不影響指紋的時間與說明。
