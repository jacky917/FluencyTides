## 1. 問題與動機

- 三語卡沒有圖譜（[speaking_trilingual_handler.py:182](../../backend/app/services/task_handlers/speaking_trilingual_handler.py) `GraphCapability(reason="口說卡沒有知識圖譜")`）。
- 使用者想要的不是單字卡那種關聯網，而是**主題 → 子情境**的階層：一張主題卡底下有很多子卡，子卡也可以再有子卡（1 對多）。
- **Anki 的卡片之間不能跳轉**，所以階層要用 Anki 本身就能瀏覽的東西表現：**卡片和一個同名的子牌組放在同一層**，子卡放進那個子牌組。這樣在 AnkiDroid 與桌面版用牌組清單就能一層層點進去，複習一個主題就是複習那個牌組。
- 網頁圖譜照這個結構畫成樹，可以設定顯示幾層；只顯示一層時，要點進去才看子層。
- 現況（2026-11-22 以 AnkiConnect 唯讀盤點）：37 張三語卡，`Prompt` 長 15–78 字（中位數 45），沒有 `Title`；牌組已經是分類樹（例如 `日常會話::日本語面接::Queen Bee Capital株式会社::最終面接` 14 張、`日常會話::お花屋さんで花を買う` 6 張），但牌組上沒有對應的主題卡。這些純分類牌組依 D5 畫成牌組節點、可以進入，舊資料不用改就能瀏覽。

示意圖（2026-11-22 與使用者確認）：

```
口說三語（牌組）
├─ 婉拒加班（卡）
├─ 婉拒加班（牌組）← 和上面那張卡同名
│   ├─ 婉拒主管（卡）
│   ├─ 婉拒主管（牌組）
│   │   └─ 主管再三拜託（卡）
│   ├─ 婉拒同事（卡）
│   └─ 婉拒飯局（卡）
├─ 租屋（卡）
├─ 租屋（牌組）
│   ├─ 反映漏水（卡）
│   └─ 續約談租金（卡）
└─ 職場求助（卡）← 沒有子卡，就沒有同名牌組
```

## 2. 目標與非目標

**目標**
- G1 三語卡有短標題 `Title`；有 `Title` 的卡，若同一層有同名子牌組，子牌組裡的三語卡就是它的子卡。
- G2 圖譜以牌組樹選到的牌組為根，畫出這一層的卡與子卡；層數可設 1、2、3 或全部，超出層數的子卡收成數字。
- G3 點有子卡的節點就進入它的子牌組（左側牌組樹同步選到那一層）；點沒有子卡的節點開卡片詳情；根節點若是主題卡也能開詳情。
- G4 網頁建三語卡時可選「建成某張卡的子卡」：系統自動建出 `<父卡牌組>::<父卡 Title>`（已存在就沿用），把新卡放進去。
- G5 結構不一致時不會壞：子牌組沒有對應的卡、卡改了 `Title` 而牌組沒改等情況，都照樣畫得出來（見 D5）。

**非目標**
- 跨主題關聯（多對多）：牌組樹只能 1 對多，跨主題的連結留到第二階段，存在 MySQL `rel_links`（§8）。
- 在網頁改 `Title`、搬移卡片、改牌組名：三語卡的欄位修改尚未開放，這次不做；只在 Anki 裡改。
- 單字卡圖譜不動。

## 3. 設計決策

### D1 新增 `Title` 欄位（使用者決定）
- `Speaking_Trilingual_Dark` 在 `Prompt` 之後加 `Title`（短標題，例如「婉拒加班」）。`Prompt` 可能是一整句，不適合當牌組名。
- 規則（建卡時檢查；Anki 裡手動改的在圖譜端寬鬆處理）：去掉前後空白、不可含 `::`（Anki 的牌組分隔符號）、不可含 `"`（搜尋語法要用引號包牌組名）、長度上限 40 字。
- 舊卡沒有 `Title`：節點名稱顯示 `Prompt` 的前 20 字，不能有子卡（沒有名字可以對上子牌組）。
- 卡片樣板：正面在 `Prompt` 上方以小字顯示 `Title`（有填才顯示），讓 AnkiDroid 裡看得出這張卡是哪個主題（Q1，使用者 2026-11-22 同意）。
- 欄位新增以 `scripts/local_anki/manage_fields.py`（`AnkiSchemaBuilder`）執行；`app/anki_models/Speaking_Trilingual_Dark.json` 的 `inOrderFields` 同步加上 `Title`；`update_templates.py` 更新樣板。

### D2 階層只看牌組結構，不另外存
- 「卡 X 的子卡」＝ X 所在牌組 `D` 底下、名稱等於 X 的 `Title` 的子牌組 `D::Title` 裡**直接**放著的三語卡（不含更深的子牌組）。更深的層照同樣規則往下找。
- 不另存 parent 欄位或資料表：Anki 裡怎麼放，圖譜就怎麼畫，兩邊不可能不同步。
- Anki 的牌組名比對不分大小寫：對應時用 `casefold()` 比對。

### D3 圖譜的節點與畫法
- **根**：牌組樹選到的牌組 `D`。若 `D` 的上一層有一張 `Title` 等於 `D` 最後一段的卡（也就是「點進來的那張主題卡」），根就畫成那張卡（點了開詳情）；否則畫成牌組節點（虛線框）。選「全部牌組」時根是一個虛擬的「全部」。
- **卡片節點**：實線框，名稱是 `Title`（沒有就是 `Prompt` 前 20 字）；右側圓點數字＝**直接**子卡數（有子牌組才顯示）。
- **牌組節點**（D5）：`D` 底下沒有同名卡的子牌組（例如純分類用的牌組），畫成虛線框，點了就進入。
- **層數**：設定 1／2／3／全部（存在瀏覽器，預設 1）。第 N 層以內展開，超出的只顯示數字。
- **畫法**：沿用 `react-force-graph-2d`，開 `dagMode="lr"`（由左往右的樹狀排版），節點改畫成圓角框加數字圓點，和單字卡的圓點節點明顯不同。不需要拖曳排版，視角記憶沿用。
- **點擊**：有子卡或是牌組節點 → 進入（`setSelectedDeck(子牌組)`，左側牌組樹同步）；沒有子卡的卡 → 開卡片詳情。上方顯示麵包屑（牌組路徑），點了可以退回。
- 能力宣告：`GraphCapability` 新增 `layout: Literal["force", "tree"] = "force"`，三語卡宣告 `GraphCapability(supported=True, layout="tree")`；前端依 `layout` 決定畫法與要不要顯示層數設定。

### D4 API 回傳的形狀
沿用 `GET /api/v1/handlers/{name}/graph?deck=…`，新增 `depth`（1–5，`0`＝全部，預設 1）。回傳延伸既有的 `nodes`／`links`：
- 節點多 `kind`（`card`／`deck`／`root`）、`deck`（節點代表的牌組或卡所在的牌組）、`child_deck`（可進入的子牌組；沒有就 `null`）、`child_count`（直接子卡數）、`depth`。
- 連線 `label="child"`，由父節點指向子節點。
- 根節點也在 `nodes` 裡（`kind="root"`，可帶 `note_id`）。
- 讀 Anki 的方式：一次 `findNotes("note:Speaking_Trilingual_Dark deck:\"D\"")` 取出 `D` 以下全部三語卡（含子牌組）＋`notesInfo`，再用 `cardsInfo` 取每張卡的牌組名，在記憶體裡依牌組路徑組樹；`deckNames` 取子牌組清單（找出沒有同名卡的牌組節點）。牌組名在搜尋裡要跳脫 `*`、`_`、`"`（Anki 搜尋的萬用字元）。

### D5 結構不一致時的處理（不報錯，照樣畫）
| 情況 | 畫法 |
|---|---|
| 子牌組沒有同名卡（純分類牌組，或卡被刪了） | 牌組節點（虛線框），可以進入 |
| 卡有 `Title` 但沒有同名子牌組 | 一般卡片節點，沒有數字 |
| 卡在 Anki 改了 `Title`，子牌組沒跟著改 | 卡變成沒有子卡；舊子牌組變成牌組節點。圖譜上兩者並排，看得出要手動對齊 |
| 同一層兩張卡 `Title` 相同 | 子牌組只算給第一張（依 nid），另一張節點標「標題重複」提示 |
| 舊卡沒有 `Title` | 名稱用 `Prompt` 前 20 字，沒有子卡 |

### D6 建成子卡（網頁建卡）
- 牌組模式不變；三語卡的建卡參數新增 `parent_note_id: int | None`（Q2）。
- 建卡參數新增必填的 `title`（Q3）；網頁草稿階段由 LLM 一併產生建議標題，使用者可以改。
- 有 `parent_note_id` 時：讀父卡的牌組 `D` 與 `Title`（父卡沒有 `Title` → 422「父卡沒有標題，不能建子卡」），目標牌組＝`D::Title`，`create_deck`（已存在不會出錯），再把新卡建在那裡。沒有時照現在建在選的牌組。
- 前端建卡畫面多一個「建成哪張卡的子卡」的選擇（搜尋三語卡標題）；從圖譜節點的卡片詳情也可以直接「在這張卡底下建子卡」，帶入 `parent_note_id`。

## 6. 風險與未知

- **Anki 的牌組名比對**：大小寫不分、前後空白會被 Anki 去掉、`::` 是分隔符號。應對：`Title` 寫入前正規化與檢查；比對用 `casefold()`。
- **一次讀很多卡**：選「全部牌組」或很大的牌組時，`notesInfo`／`cardsInfo` 可能要讀上千張。應對：只讀三語卡；層數只影響回傳，不影響讀取量，先量測，太慢再改成依層讀。
- **改 `Title` 後牌組不會跟著改**：這次不提供改名功能（三語卡欄位修改未開放），D5 讓不一致看得出來。之後開放修改時，要同時「建新牌組 → 搬卡 → 刪舊牌組」（AnkiConnect 沒有改牌組名的動作）。
- **複習上層牌組會連子卡一起出現**：這是 Anki 的行為，符合「複習一個主題」的用途，不處理。
- **`dagMode` 的排版**：react-force-graph 的 DAG 排版遇到很多同層節點時可能重疊。應對：P3 先用 30＋ 節點的測試資料看效果，不行就改成自己算座標（樹狀排版不需要力導向）。
