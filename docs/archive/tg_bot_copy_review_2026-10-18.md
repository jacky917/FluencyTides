## 1. 結論

文字本身最大的問題不是冗長，而是**會讓使用者誤判狀態**：

1. **動態內容沒跳脫（約 20 處）**：bot 預設 `parse_mode=HTML`（`dispatcher.py:93`），使用者輸入、Anki 欄位、例外訊息只要含 `<` 或 `&`，那則訊息就送不出去。多數發生在**寫入已完成之後**，畫面停在「⏳ 處理中」，使用者以為失敗而重做——刪除流程會因此刪到下一筆。
2. **文字與實際狀態不符**：說「稍後再試」但狀態已清；說「正在查字典」但沒呼叫 LLM；說「同步」但沒同步；說「已取消對話卡」但取消的是別的流程；說「傳現成的音檔」但只收語音訊息。
3. **反引號在 HTML 模式原樣顯示**（外語糾錯、對話卡、/setconfig），`/skip` 包在反引號裡也不能點。

其餘是精簡與一致性：內部術語外露（Card ID、Payload、索引、BCP-47、Bot 實例、回滾、類別名）、每則成功訊息都帶「！」「🎉」「本地」、同一件事 3～4 種說法。

## 2. 全 bot 用語規則

| 情境 | 寫法 | 範例 |
|---|---|---|
| 處理中 | `⏳ {動作}中…`，一行，不加粗 | ⏳ 寫入 Anki 中… |
| 成功 | `✅ 已{動作}` + 必要結果；不加「！」「🎉」「本地」 | ✅ 已寫入 Anki：母卡 1 張＋子卡 3 張 |
| 部分成功 | `⚠️ 已{動作}，但{問題}；{下一步}` | ⚠️ 已寫入 Anki，但同步 AnkiWeb 失敗；下次操作會再試。 |
| 失敗 | `❌ {什麼}失敗：{原因}` + 下一步 | ❌ 建立失敗：可能是重複卡片。請用 /newcard 重新開始。 |
| 取消／放棄 | `🗑️ 已取消。`／`🗑️ 已放棄，未寫入任何卡片。` | |
| 過期 | `⌛ 已過期，請{入口}。` | ⌛ 已過期，請回 Anki 重新點按鈕。 |
| 無權限 | `⛔ 您沒有使用權限。`／`⛔ 只有管理員可以使用 /xxx。` | |
| 未設定管理員 | `⛔ 系統未設定管理員（TG_ADMIN_CHAT_ID），/xxx 目前無法使用。` | |
| 找不到卡片 | `❌ Anki 裡找不到這張卡片（可能已刪除或尚未同步）。` | |
| 連不上 Anki | `❌ 連不上 Anki，請確認電腦版 Anki 已開啟。` | |
| 未開放 | `🚧 {功能}尚未開放。` | |
| 引導（非錯誤） | `💡 …` | 💡 用 /newcard 新增卡片，/help 查看說明。 |
| 按鈕 | `⬅️ 上一步`（FSM）、`⬅️ 返回`、`◀️ 上一頁`／`下一頁 ▶️`、`⏭️ 跳過`、`❌ 取消`、`✖️ 關閉` | |

另外：

- **下一步要能照做**：清掉狀態的失敗訊息要說重新進入的入口（「請用 /newcard 重新開始」「回 Anki 重新點按鈕」）；沒清狀態的說「請再傳一次」。
- **不給使用者看的字**：Card ID、Note ID、Payload、索引、欄位英文名（References、Prompt_Audios）、類別或例外名、「本地」「實例」「回滾」「初始化」「BCP-47」。
- **不要英文括號**：`(Speaking Coach)`、`(Target Language)`、`(Front/Prompt)`、`(Answers)` 等一律拿掉；只保留代碼（`en-US`）與模型名。
- **用詞**：寫進 Anki 用「寫入」、產生卡片用「建立」、AI 產出用「生成」；外語糾錯的「高階重組／高階表達／重組」統一為「道地重組」。
- **emoji 一詞一義**：🎙️ 錄音、📤 上傳音檔、💬 對話卡（目前三者都用 🎙️）。
- **標點**：冒號一律全形「：」，省略號用「…」。
- **格式安全**：動態內容一律 `escape_tg()`／`html.escape()`，錯誤字串**先截斷再跳脫**；alert ≤ 190 字元；callback data 以 **bytes** 計 64。

## 6. 順帶發現：不是文字、但會造成錯誤的行為（建議另開項目）
