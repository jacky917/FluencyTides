§1

訊息進來後怎麼走

Telegram 推送先過 webhook 密鑰比對，再經兩層中介層。之後 aiogram 依 router 註冊順序逐一比對，第一個符合條件的處理器接手，後面的就不再看。這個順序決定了很多行為，例如語音與圖片先於 FSM 被攔下，而一般文字要等三條 FSM 都不認領才會落到最後的兜底回覆。

§2

兩套互不相通的狀態系統

新增卡片的三條流程用 aiogram 內建的 FSM；從 Anki 卡片點進來的錄音與上傳音檔，則用自寫的 UserStateManager。兩者各自記錄、互相看不到對方。

系統用在哪狀態存放與過期
aiogram FSM /newcard 的三條流程 外語糾錯 8 個、對話卡 5 個、單字卡 1 個 預設 MemoryStorage；不會過期，後端重啟即全部消失
UserStateManager Deep Link 錄音、上傳音檔、頭像 recording add_audio wait_avatar_selection wait_avatar_upload wait_speaker_name 記憶體；10 分鐘過期（TG_STATE_EXPIRE_MINUTES），重啟即消失

§4

各流程的狀態轉換

4.1 外語糾錯

ExpressionStates · 8 個狀態

最長的一條。每一步都有「返回上一步」按鈕，圖中以「返回」標出。在呼叫 LLM 之前，先到 Anki 查有沒有同原文的母卡，避免白花 token。

stateDiagram-v2
  state "waiting_for_lang：語言對" as lang
  state "waiting_for_text：外語原文" as text
  state "waiting_for_context：情境" as ctx
  state "waiting_for_source_tag：來源標籤" as tag
  state "waiting_for_grammar_correction：文法修正版" as gram
  state "waiting_for_reorganization：高階重組版" as reorg
  state dup_check <<choice>>
  state "waiting_for_duplicate_decision：重複怎麼辦" as dup
  state "呼叫 LLM 產生預覽" as llm
  state "waiting_for_card_selection：選要寫入的子卡" as sel

  [*] --> lang : 選「外語糾錯」
  lang --> text : 輸入「中文→日文」（或 /skip 用預設）
  text --> ctx : 輸入原文
  ctx --> tag : 輸入情境（或 /skip）
  tag --> gram : 點標籤 / 打字 / 跳過
  gram --> reorg : 輸入修正版 / 跳過（交給 AI）
  reorg --> dup_check : 輸入重組版 / 跳過（交給 AI）
  dup_check --> llm : 查無重複（查詢出錯也直接往下）
  dup_check --> dup : Anki 已有同原文母卡
  dup --> llm : 覆蓋舊卡 / 允許重複
  dup --> [*] : 取消糾錯
  llm --> sel : 預覽成功
  llm --> [*] : 生成失敗
  sel --> [*] : 全部添加，或輸入編號 → 寫入 Anki
  sel --> [*] : 全部放棄
  sel --> sel : 編號無效 → 重新詢問
  sel --> reorg : 返回修改重組
  text --> lang : 返回
  ctx --> text : 返回
  tag --> ctx : 返回
  gram --> tag : 返回
  reorg --> gram : 返回

選擇「覆蓋舊卡」時，真正的刪除發生在最後寫入 Anki 時（級聯刪除舊母卡與子卡），不是在選擇當下。

4.4 錄音評分與上傳音檔

UserStateManager · 5 個狀態

從 Anki 卡片上的按鈕點進 Bot，Deep Link 的格式是 {動作}-{欄位}-{序號}-{Card_ID}。進入狀態前會先確認 Anki 裡找得到這張卡。

stateDiagram-v2
  state "recording：等語音（評分）" as rec
  state "add_audio：等語音（上傳）" as add
  state "wait_avatar_selection：選頭像" as sel
  state "wait_avatar_upload：等圖片" as up
  state "wait_speaker_name：等說話者名稱" as name

  [*] --> rec : /start rec-…（卡片存在）
  [*] --> add : /start addaudio-…（卡片存在）
  rec --> [*] : 傳語音 → 上傳 Media → AI 評分 → 寫回錄音欄位
  add --> sel : 傳語音 → 上傳 Anki Media
  sel --> sel : 打開系統頭像清單 / 返回
  sel --> [*] : 點某個系統頭像 → 寫回（說話者＝檔名）
  sel --> [*] : 跳過 → 寫回（說話者＝User）
  sel --> up : 上傳自訂圖片
  up --> name : 傳圖片 → 存到 assets/avatars 與 Anki Media
  name --> [*] : 輸入名稱 → 寫回
Deep Link行為
rec-…顯示題目，進入 recording，等使用者傳語音
addaudio-…進入 add_audio，等使用者傳現成音檔
del-…不進入任何狀態，直接刪除該欄位的指定條目並寫回 Anki（沒有確認步驟）
gen_…回覆「生成卡片操作尚未實作」

沒有進行中的任務卻傳了語音：回覆「目前沒有進行中的錄音任務」。沒有在等圖片時傳圖片：靜默忽略。

§5

交互規則與已知坑

  • 衝突
    兩套狀態同時存在時，文字會先被 FSM 吃掉

    例如在外語糾錯流程中途點了 addaudio 連結並走到「輸入說話者名稱」，打的名稱會被 FSM 當成糾錯流程的輸入（FSM 排在兜底 router 之前），頭像流程收不到，10 分鐘後過期。

  • 卡住
    沒有全域取消

    /start、/help、/sync、/setconfig 在流程中都能用，但不會清除 FSM 狀態。外語糾錯沒有取消按鈕，只有遇到重複時的「取消糾錯」和預覽時的「全部放棄」。FSM 不會過期，想離開只能 /newcard 重新開始（會覆蓋）或等後端重啟。

  • 舊按鈕
    「返回」與對話卡「取消」按鈕不檢查目前狀態

    expr_back_*、speak_back_*、speak_cancel 沒有綁狀態過濾。點聊天紀錄中舊訊息上的返回鈕，會把已經結束的流程重新拉回那一步。單字卡的取消有綁狀態，不受影響。

  • 殘留
    評分服務未初始化時，錄音狀態不會清除

    recording 收到語音後，音檔已先上傳到 Anki Media，接著發現評分器不可用就直接結束，狀態留到 10 分鐘過期。

  • 重啟
    兩套狀態都只存在記憶體

    部署或重啟後，所有進行到一半的流程都會消失，使用者需要重新開始；Deep Link 的錄音任務要重新點卡片上的按鈕。

  • 未實作
    gen_ Deep Link 與自由輸入的設定

    gen_… 只回覆尚未實作；/setconfig 裡沒有選項清單的設定無法在 Telegram 修改。

  • 授權
    白名單沒設定時一律擋下

    TG_ALLOWED_USER_IDS 為空時所有人都被擋，而且不回覆任何訊息，只在 log 留紀錄；名單外的人則會收到「沒有權限」。
