§1

訊息進來後怎麼走

Telegram 推送先過 webhook 密鑰比對，再經兩層中介層。之後 aiogram 依 router 註冊順序逐一比對，第一個符合條件的處理器接手，後面的就不再看。這個順序決定了很多行為，例如語音與圖片先於 FSM 被攔下，而一般文字要等三條 FSM 都不認領才會落到最後的兜底回覆。

兩套互不相通的狀態系統

4.1 外語糾錯

ExpressionStates · 8 個狀態

最長的一條。每一步都有「返回上一步」按鈕，圖中以「返回」標出。在呼叫 LLM 之前，先到 Anki 查有沒有同原文的母卡，避免白花 token。

stateDiagram-v2
  state "waiting_for_lang：語言對" as lang
  state "waiting_for_text：外語原文" as text
  state "waiting_for_context：情境" as ctx
  state "waiting_for_source_tag：來源標籤" as tag
  state "waiting_for_grammar_correction：文法修正版" as gram
  state "waiting_for_reorganization：高階重組版" as reorg

  state "waiting_for_card_selection：選要寫入的子卡" as sel

  [*] --> lang : 選「外語糾錯」
  lang --> text : 輸入「中文→日文」（或 /skip 用預設）
  text --> ctx : 輸入原文
  ctx --> tag : 輸入情境（或 /skip）

4.6 LLM 模型選單 /models

不使用狀態，按鈕自帶位置

管理每個 LLM 用途（例如 jp_verb_pair、jp_verb_reading）與全域 * 該用哪個端點、模型與思考深度（effort）。選項只來自 .env 的白名單，寫入與 API /api/v1/capability-routes 共用同一個服務（白名單檢查＋試建一次客戶端），存在資料庫的 capability_routes 表（llm 能力），下一次生成即生效、重啟後仍在。沒有任何 FSM 或 UserStateManager 狀態：每個按鈕的 callback data 寫成 lr:<動作>:<版本>:<序號…>，自帶目前選到哪一步，以序號代替名稱以符合 Telegram 的 64 位元組上限。

規則行為
舊按鈕偵測「版本」是用途清單＋端點白名單的 6 碼雜湊，每次按鈕都重新計算比對。清單變了（重新部署改了 .env、刪了孤兒鍵）或序號、格式無效時一律提示「選單已過期，請重新輸入 /models」，不會誤改別的用途。關閉鈕 lr:x 不帶版本，任何時候都能按
授權指令與每個按鈕都檢查 TG_ADMIN_CHAT_ID；未設定管理員時整個選單無法使用
讀不到資料庫清單照常顯示（皆為 .env 預設並附警示），但除關閉鈕外的所有按鈕都被拒絕（唯讀），避免把「讀不到」當成「沒有設定」
解析順序用途自己的設定 → 全域 * → .env；不在白名單的設定被略過並在詳情標示。改的是 * 時另重建診斷用的全域客戶端
與其他流程不讀寫任何狀態，在 FSM 流程中途也能用（router 排在 FSM 之前），用完後原流程的狀態不變

「⬅️ 返回清單」會回到該用途所在的頁。儲存後若更新畫面失敗，Bot 會明說「已儲存」，不會把已寫入的設定報成失敗。

§5

交互規則與已知坑

  • 衝突
    兩套狀態同時存在時，文字會先被 FSM 吃掉

    例如在外語糾錯流程中途點了 addaudio 連結並走到「輸入說話者名稱」，打的名稱會被 FSM 當成糾錯流程的輸入（FSM 排在兜底 router 之前），頭像流程收不到，10 分鐘後過期。

  • 卡住
    沒有全域取消

    /start、/help、/sync、/setconfig、/models 在流程中都能用（它們的 router 排在 FSM 之前，且不帶狀態過濾），但不會清除 FSM 狀態。外語糾錯沒有取消按鈕，只有遇到重複時的「取消糾錯」和預覽時的「全部放棄」。FSM 不會過期，想離開只能 /newcard 重新開始（會覆蓋）或等後端重啟。

  • 舊按鈕
    「返回」與對話卡「取消」按鈕不檢查目前狀態

    expr_back_*、speak_back_*、speak_cancel 沒有綁狀態過濾。點聊天紀錄中舊訊息上的返回鈕，會把已經結束的流程重新拉回那一步。單字卡的取消有綁狀態，不受影響。/models 的按鈕以版本雜湊偵測過期（§4.6），也不受影響。

  • 殘留
    評分服務未初始化時，錄音狀態不會清除

    recording 收到語音後，音檔已先上傳到 Anki Media，接著發現評分器不可用就直接結束，狀態留到 10 分鐘過期。

  • 重啟
    兩套狀態都只存在記憶體

    部署或重啟後，所有進行到一半的流程都會消失，使用者需要重新開始；Deep Link 的錄音任務要重新點卡片上的按鈕。

  • 未實作
    gen_ Deep Link 與自由輸入的設定

    gen_… 只回覆尚未實作；/setconfig 裡沒有選項清單的設定無法在 Telegram 修改。

  • 授權
    白名單沒設定時一律擋下

    TG_ALLOWED_USER_IDS 為空時所有人都被擋，而且不回覆任何訊息，只在 log 留紀錄；名單外的人則會收到「沒有權限」。
